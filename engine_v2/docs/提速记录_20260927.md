# 一步 41 ms 到 13.7 ms：每一步的时间花在哪，动了什么

现场：`models/reflex_arena.xml`，40.8 万细胞 / 118 万连接，每只眼 160×120，
引擎 cuda。所有数字来自同一台机器、同一份配置，改完再量一遍，不是估算。

## 一、量出来的账（`tools/profile_live_step.py`，80 步取均值）

| 阶段 | 改前 ms | 改后 ms |
|---|---|---|
| 眼睛（渲染 + 缩成感光细胞） | 4.20 | 3.74 |
| 大脑 `brain.step` | 11.79 | 9.01 |
| 身体感觉 / 耳朵 / 物理 | 0.56 / 0.17 / 0.58 | 0.19 / 0.15 / 0.59 |
| **整步** | **16.93** | **13.69** |
| 步/秒 | 59.1 | **73.1** |

实时窗口（`运行模型.ps1`）里同一次 `brain.step` 从 **15.84 ms 降到 8.26 ms**，
`sim_speed` 从 **0.222 升到 0.515**，也就是端到端一步 **45 ms 变 19.4 ms**。
窗口里狗直立（`up_z 0.99995`）、前进 0.60 m、`body_resets 0`、`error: null`。

## 二、最大的一笔：听觉回路每样本 21 次 numpy 调用

`AuditoryNeurons.step` 一次吃 160 个采样（10 ms 的 16 kHz 波形），原来对每个采样
单独做一遍受体电流、四次花式索引赋值、一次 `np.array([1., -1.])`。整步 4 ms 里
3.8 ms 是这段 Python/NumPy 的调用开销，不是算术。

改法是等价的：受体电流只由波形决定、不读细胞状态，于是整块预算一次
（`(samples, cells)` 的一行），循环里只剩递推本身，并且写进预先分配好的缓冲区。
`np.clip` 换成 `np.minimum`+`np.maximum`（同一个夹取，省掉 fromnumeric 包装）。

**逐位相同**（`artifacts/_bench_auditory.py`：电压、适应、轴突环与游标全等，差 0.0），
**4.16 ms → 1.41 ms**。全量测试里的 `AUDITORY_BENCHMARK`：**11.41 ms → 4.25 ms**（每 512 采样）。

试过但更慢、已放弃：`np.add.reduceat` 做视网膜的行和（1.59 ms，按段调用开销大）。

## 三、第二笔：一张 40 万向量被拷三遍、校验三遍

`InnateController.step` 自己造了激励向量，交给网络时最外层又 `np.array(copy=True)`
拷一份（0.51 ms）。现在多了一个 `step_owned` 入口：调用者本来就是这张向量的主人，
就直接在这张向量上加像素电流，不再拷第二份。对外入口 `step` 的语义没变（仍然拷贝，
仍然不写调用者的数组）。

同一张向量原来被 `_checked_in_place` 从头到尾扫三遍（每遍 0.14 ms），三遍都保留：
每一层的 `+=` 都可能引入非有限值，这一条是判定，不是开销。

## 四、第三笔：每次 `bool(...)` 都要等一次显卡

`torch.isfinite(a).all() and torch.isfinite(b).all() and ...` 里的 `and` 会在第一个
谓词处求值并各自等一次显卡；一步里有 7 次这样的等待。改成在显卡上用 `&`/`|` 合成
一个谓词、只 `bool()` 一次（3 次等待）。三个谓词一个没少。

## 五、其它

- `EmbodiedController.step` 里像素电流改成原地除进网络已有的向量（`np.divide(..., out=)`），
  少一次 921 KB 的分配。
- `AdaptiveNetwork`、`FeatureInputNetwork`、`ReflexInputNetwork`、`RetinalInputNetwork`
  都提供 `step_owned`，整条链只拷一次（这一条是上一轮做的，本轮把最外层也接上）。

## 六、证明没改坏

- `tools/compare_engines.py`（200 步、49042 细胞）：两次重跑仍逐位相同；跨引擎
  `activity` 最大差 **2.773e-13**、`voltage` **2.773e-13**、`weights` **8.882e-16**、
  身体位置六位小数 —— 与改动前的记录 **一字不差**。耗时 host 18.63→12.22 ms/步、
  device 11.19→6.69 ms/步。
- `tools/probe_resolution_behaviour.py 400`：五个分辨率的前进 / 位移 / 末高度 /
  最低高度 / 最小 up_z **逐列与改动前完全相同**（0.169/0.176/0.182/0.183/0.181 等），
  只有耗时从 43.2 s 降到 18.3 s。
- 全量测试 153 项全过（169 s，原 197 s）。

## 七、还剩什么

- `Segmented` 的定宽行设计带来约 4.6 倍填充（118 万连接 → 516 万槽位），
  这是为“重跑逐位可复现”付的代价；要提速得改归约方案，会改浮点尾差，先不动。
- `host_rate` 每步把 40.8 万速率传回主机再 `np.clip`（约 1 ms），
  主机只读其中几千个数（运动、募集）。要省这笔得改 `activity` 的公开语义，先不动。
- 视网膜行和前的 `uint8 → float32` 转换 0.44 ms/眼，是 `_report` 现在最大的一行。
