## 一、这套东西长什么样

```
python tools/taskbank.py --list                    # 116 道题一行一道
python tools/taskbank.py --tree                    # 先修阶梯：哪道题要先过哪道
python tools/taskbank.py --explain                 # 每题：问什么、量什么、门槛多少、出厂读数
python tools/taskbank.py --unlocked walk_flat,eyes_follow_ball   # 这几道过了，接下来能考什么
python tools/taskbank.py --stage full --seeds 0 1 2 --output artifacts/exam_birth_full.json
python tools/taskbank.py --birth-text --birth-source artifacts/exam_birth_full.json
```

- **一道题 = 建一个场景 → 读几个数 → 和一个写死的门槛比一比。**
- 题目**从不决定动作**。它只看身体最后到了哪、全程有没有倒、哪个细胞群亮了多亮。
- 两个候选之间**只有出生连接不同**：47 个具名先天增益 + 抽支架的种子。
  结构、尺寸、传感器、学习规则一个字都不动。
- 参考尺寸固定为 `motor 200 / proprio 64 / association 256 / eye 48x36`。

## 三、先修阶梯（7 级）

阶梯的规则：一道题的**所有**先修题都过了，它才开。所以一只不会站的动物
不会被要求上坡。

```
第 0 级  站着不动 / 仰面翻身 / 眼睛跟着球 / 突然一声会受惊 / 能被教会一件事 / 配对过的图案有意义
第 1 级  各感觉的最基本一档（走一步、侧躺翻身、追快球、左右声音、身上被碰、
         往哪边歪、快倒了护住自己、没人教不会、隔一会还记得……）
第 2 级  满场走一段、被外部指令驱动着走、脚不打滑、过窄道、近远、前后声音、
         脚被绊抬那只、听腻了还听得见、自己的晃动 vs 被推、被用力推倒还能起来
第 3 级  一直走、走直、不走偏、走快了、一边走一边朝声音转、被顶着不走、突然一声停下、
         四只脚都要抬、左右要对称、过窄道不蹭墙、背后有声音不偏、安静不是声音、平地不是坎
第 4 级  上坡、迈坎、走二十秒、走十六秒、从台阶上下来、绕开挡板、走久了不慢下来、
         一边走一边转还继续走、被顶胸口要后退、撞墙不翻、两条腿都查、前腿承重
第 5 级  上台面、顺坡下来、三十秒
第 6 级  从台面上走下来
```

主干线（用户点名的那条）是：

```
站得住 → 走得动 → 走得远/走得快 → 会转弯 → 会上下地形 → 一边走一边做别的事
```

`--tree` 会把整张阶梯打出来，`--unlocked 题名,题名` 会告诉你"已经会这些，
接下来能考什么"。
## 四、门槛是从哪来的

每条门槛都有出处，写在 `taskbank.BAR` 里，两种来源：

- **仓库里本来就有的判据**，直接引：`validate_reflex_v3.behavior_pass`（全程不倒）、
  `probe_righting.recovered`（站住了并且没再倒）。走路的题、自救的题用的都是这两条。
- **先量出厂动物，再留余量定门槛**。出厂读数写在 `taskbank.BIRTH` 里，
  `--explain` 会把"读数 / 门槛 / 这题不证明什么"三行并排打出来，一条也不用猜。

规则是死的：

- **门槛不许为了让出厂动物好看而改**。出厂动物过不了的题是故意留着的：
  题库要比动物宽，候选才有地方长。
- **每题都要写"这题不证明什么"**，`--explain` 会打出来。写得含糊的题就是坏题。
- **每个门槛都得能说"不"**：`tests/test_taskbank.py` 里有一组测试专门拿一个
  失败的结果去问每道题的判据，谁答"过"就报错。

## 五、这 116 道题测不了什么（必须一起看）

这一节是这份文档里最该看的一节。第三批设计题目的过程中，实测撞到四件事，
它们直接决定了哪些题**不能**出，以及哪些题的题名其实名不副实。

### 5.1 外部前进指令这条线在考试尺寸下是死的（最严重）

同一个种子 0、同一只出厂动物、同样 8 秒，只换驱动方式：

| 场景 | 参数 | 8 秒走了多少米 | 平均速度 |
|---|---|---|---|
| `rest` | 不自主，前进输入 0.0 | 0.5570 | 0.108 m/s |
| `autonomous` | 自主，前进输入 0.0 | 0.5570 | 0.108 m/s |
| `driven` | 不自主，前进输入 0.65 | 0.5574 | 0.108 m/s |
| `amble` | 不自主，前进输入 0.35 | 0.5578 | 0.108 m/s |
| `sprint` | 不自主，前进输入 1.00 | 0.5575 | 0.108 m/s |

**五个场景走出来的距离在小数点后第三位才分开。** 也就是说 `locomotion` 这个输入
和 `autonomy` 这个开关，在这一档尺寸下都没有接到步态上；出厂动物是自己在那儿
蹭着走的。后果：

- `walk_when_driven`（"外面给一个前进指令，它会不会走"）和
  `keeps_walking_when_driven`、`does_not_slow_down_on_a_long_walk`、
  `keeps_its_line_with_a_sound_behind`、`backs_away_from_a_hand_on_its_chest`
  这些用 `driven` 场景的题，现在**实际测的是"它自己走不走"**，不是"它听不听指令"。
  这一点写进每道题的说明了，但题名还叫 driven。
- 用户之前想做的那条"声音 → 走路"的外部通路，靠的就是这一路。它现在是断的。

**这不是题的错，是引擎接线的错。** 两条路：要么修（把 `locomotion`/`autonomy` 真正接到
步态募集上），要么把用 `driven` 的题全部改成自主场景并且改名。**2026-09-28 深夜走了第二条**：
用 `driven` 的题全部改成 `autonomous`，题名里的 `driven` 换成 `without_being_told` / `walk_owns_...`，
门槛键 `walk_driven_m` 一类改成 `walk_own_m`；同时把刻意拧的「前进指令旋钮」从题库里删干净
（`walks_faster_when_the_world_asks_for_it` 改成 `hurries_towards_a_bright_thing`——前面放一个亮
东西 vs 空房间，比的是两边平均速度之比，而不是去拧指令；`runs_when_the_world_asks_for_it`
改成 `runs_without_being_told`）。这样题目问的就是「它自己走不走」，和引擎现在真实接的线一致。
改完之后的门槛和出厂读数见 `docs/题库_第四批_20260928.md`。

### 5.2 "东西冲过来变大"那条线是死的，所以那道题删了

- `eye_growing` / `eye_looming` / `eye_swell_left` 这一路，把球从半径 0.06 涨到
  1.20、再从 1.00 涨到 2.00，读数都是 **0.00000**。
- 上游 `retinal_rise` 有 0.00142、`retinal_fall` 有 0.00954，也就是说画面本身
  是变的，是**下游没接**。

第二批里那道 `eyes_see_a_thing_rush_in` 就是用"球在视野里扫过"冒充"变大"的，
而且它的度量函数 `loom_measure` 已经被删掉、题却没删干净，跑起来是 `NameError`。
第三批把这道题**删掉了**，换成两道诚实的：`sees_a_big_ball_from_a_small_one`
（比大小，不是比逼近）和 `the_hidden_layer_sees_the_picture`（画面有没有带下去）。
要恢复"变大"这道题，得先把 `eye_growing` 这一路接上。

### 5.3 眼睛的上下（俯仰）几乎不动

球上下扫过 300 帧，眼球俯仰指令只动了 **0.0265 弧度**，与球真实仰角的平均差
**0.256 弧度**（约 15 度）。所以 `eyes_follow_the_ball_up_and_down` 的门槛按这个
读数定（0.22 弧度），出厂动物**过不了**。这是故意的：这一题现在是一条"待爬的坡"，
不是一条已经接好的线。

### 5.4 两只眼睛"一致不一致"那层是常量，所以没出这方面的题

`eye_bands_agree` 在"眼前有个球"和"空房间"两种情况下都读 **0.9767**，
一样的数。既然它不随世界变，就没有任何题可以拿它量。同样的还有
`eye_distance`：球在近处反而比远处**低**（0.1202 → 0.1044），方向是反的。

### 5.5 一句话总结

这 116 道题里，**能信的**是：站立、步态质量、地形、自救、大部分视觉/听觉/触觉的
分辨、学习与记忆、以及"它自己"的那几道。**不能信的**是所有靠"外部驱动"这个前提
的题（5.1），和所有靠"逼近/变大"这个前提的题（5.2）。
## 六、还差什么才算"完整题库"（诚实清单）

用户问的是"能不能做到足以训练出自我意识"。按现在的引擎，答案分两半：

**能做到的**：把"一个生物有没有做到某件事"变成过/不过。这 116 道题里，
站立、步态、地形、自救、感觉分辨、学习、记忆、注意、以及"它自己"的那几道
都能这么问，而且每条都有出处。

**还做不到的**，一条条列在这里：

| 缺口 | 为什么现在做不了 |
|---|---|
| 时间尺度 | 最长的记忆题只隔 60 秒。没有"天"级，因为一次考试只在几秒到一分半之间 |
| 嗅觉、味觉、温度、痛觉 | 仿真里没有这些传感器，输入层没有对应的原始通道 |
| 触觉的质地 | 身上只有 4 个分区、脚只有 4 个通道，只有"有没有、在哪"，没有轻重之外的质地 |
| 听觉的内容 | 只有 262 Hz 和 880 Hz 两个声源，做不出旋律、节奏、音色 |
| 发声 | 模型不会发出声音，所以"听见自己的声音""自己的声音 vs 别人的声音"这一类做不了 |
| 社交 | 场里只有一个个体，模仿、被叫名字、轮流做不了 |
| 内感受 | 有疲劳和奖赏各一个细胞，但没有"饿/累/疼"这一层内部读数可读 |
| 自我 | 只有 3 道，而且都是"某个读数在不在"。真正要问的是"这个变化是我弄出来的还是外面弄出来的"，那需要引擎里先有"发出去的动作副本"这一路——现在没有 |
| 镜子/看见自己 | 没有镜子，也没有把眼睛指向自己身体的回路 |
| 全尺寸 | 所有题跑在考试尺寸（motor 200 / eye 48x36）上；实时窗口那档（1600 / 192x144）没测过 |

## 七、怎么加题（留给后面的人）

加一道题是四步，缺一步这题就是坏题：

1. **建场景**：用 `cell_read` / `walk_measure` / `contrast_read` / `righting_measure`
   这些现成的架子，能拼就不写新的；非得写新的（比如上面的 `sound_gap_measure`）
   就照它们的样式写。
2. **读几个数**：只能是身体最后到了哪、全程有没有倒、哪个细胞群亮了多亮。
   不许在题里替脑子算距离、方位、意义。
3. **定门槛**：先在出厂动物身上量一遍，把读数写进注释，再留余量写进 `BAR`。
   出厂动物过不了没关系（题库要比动物宽），但**必须写清楚它过不过**。
4. **写说明**：`TASK_DOC` 里两句话——"量什么""门槛是多少"，外加 `note` 一句
   "这题不证明什么"。少了任何一句，`tests/test_taskbank.py` 会报错。

先修（`requires=`）顺手写：一道题只要点了先修，`--tree` 和 `--unlocked` 就认它。
