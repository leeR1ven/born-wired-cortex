# 题库与训练方式自审（2026-09-29 晚）

这一份是自己审自己：把题库和训练流程当成要检验的东西，而不是当成工具用。所有数字都配了
脚本名和产物名，可以重跑。

## 0. 一句话

把 130 道题在出生动物身上全跑了一遍，据此（一）重做了便宜的筛选档，（二）补了 4 道缺的题，
（三）把前额叶回肌肉的返回线改成天生就有，（四）写了并行筛选器，然后开了一场真筛选，
（五）把每步都在算却每步都扔掉的那份诊断读数砍掉、给筛选档加了"第一道不过就停"的链。
过程中发现**两道题是废的、一道题的读法是错的、一个基因在搜索里等于不存在、题库对自己说的话
是死文本**，以及一个**关于"种子"的根本误解**——下面逐条摆出来。

时间那一块单独放在第 7 节：**一道 10 秒的走路题从 15.3 秒降到 9.3 秒（省 37~39%），读数逐位不变；
同一批 24 个候选，筛选从 342 秒降到 19 秒（快 18 倍）。数字都能重跑：
`python tools/measure_step_cost.py parts|build|walk-ab`，落盘在 `logs/测速_*.log`。**

### 1.3 "三种子"是什么意思——一个根本误解（已更正）

我今晚一度把 `nose_down_recover` 的 1/3、`stay_up_when_pushed` 的 2/3 读成"这道题在掷硬币"。
**错了。** 查代码：

| 位置 | 事实 |
| --- | --- |
| `tools/taskbank.py` `brain_for()` | `EmbodiedController(..., seed=ctx["seed"])` —— 随机脚手架用这个种子 |
| `tools/validate_reflex_v3.py` `run_seed()` | `body.reset(seed=seed)`、`np.random.default_rng(seed)` —— 物理复位和初始朝向也用这个种子 |

**一个种子同时决定随机脚手架、身体复位、初始朝向。** 所以 `--seeds 0,1,2` 是**三只不同的
随机动物**，不是同一只动物的三次重复测量。

后果有两面：

- 好的一面：`--seeds 0,1,2` 上全过，意思是"三个不同的随机脚手架下都能做到"，这比同一只
  动物重复三次强得多，是真正的鲁棒性证据。
- 麻烦的一面：这个工程里**没有**"同一只动物、不同物理噪声"的对照。所以"题不稳"和"动物不同"
  这两件事今天分不开。要分开，得把种子拆成两个参数（脚手架种子 + 物理种子）。

这一条同样适用于单基因扫描：`tools/sweep_genes.py` 固定 `--scaffold 0`，但它 `--seeds 0,1,2`
换的还是脚手架。所以扫描表里同一档的 3 个格子是 3 只不同动物，读的是"这个基因值 × 3 个脚手架"。

### 1.4 screen 那 7 道题的更正

出生动物在 128 题全库审计里是 **pass** `stay_up_when_pushed` 的。所以 screen 的 7 道题里，
出生动物真正失败的只有 `get_up_from_back` 一道——**形式上 7 道，信息上 1 道**。
（原先那份文档写的是"信息上 2 道"，已在原处更正。）

### 1.5 一个自审角度：死题和活题一样没用

这一条是从下面第 2.2 节学来的。**只看"出生动物过不过"决定一道题好不好，会造出谁都过不了的
题。** 一道谁都过不了的题，和一道谁都过得去的题，在筛选里同样等于零。所以每加一道题，至少
要两个方向各测一次：

| 方向 | 要求 | 怎么测 |
| --- | --- | --- |
| 出生动物过不过 | 想出筛子就必须不过 | `audit_taskbank.py --stage full`（默认基因组） |
| 有没有人能过 | 至少要有一个基因组能过 | `audit_taskbank.py --genome <基因组>.json`（见 2.2） |

`tools/sweep_genes.py` 顺手解决了同一件事的另一半：它一次只动一个基因、按基因自己的尺度取
五档，所以能看出"这个基因往哪个方向走分数更高"。

## 2. 补了四道题

### 2.1 有信号时走直线（你点名要的）

四道新题里的第一道按你的原话做："给他个信号……获得信号后就走直线则视为合格"。

| 项 | 内容 |
| --- | --- |
| 题名 | `keeps_its_line_towards_what_it_sees`（组：注意） |
| 问 | 前面摆个亮东西时，它走的那条线会不会更直 |
| 量 | 同一只动物两次走十秒：前面有亮东西 vs 空房间，两次直度之差 |
| 判据 | 直度至少提高 0.05 |
| 出生动物 | **过**（三种脚手架 +0.102 / +0.093 / +0.180） |
| 成本 | 29 ~ 33 秒 |

它是"描述题"不是"筛子"：出生动物本来就过，说明"有东西可看的时候更不绕"这件事在出厂动物
身上已经成立。这一点也顺便回答了打转那件事——**空房间里绕圈不是缺点**（场地就这么大），
有东西可看时更直才是能力，现在这条有了自己的读数。

### 2.2 前额叶回肌肉的返回线（你点名要的），以及两个坑

你问过"前额叶说的话，肌肉听不听得到"，也说过"前额叶要想把信息返回给其他区，只能通过
返回线"。这条线原来不存在（关联区是个封闭回路），我在上一轮加了它，但**它今天之前一直是关的
（增益 0）**，而且**我把它测错了**。两个坑：

| 坑 | 现象 | 根因 | 改法 |
| --- | --- | --- | --- |
| 读数把返回线减掉了 | 增益 1 时读数 -3e-5，等于零 | 读数用"歪着时的肌肉读数 − 站直时的肌肉读数"。关联层在两个相位都亮（站直 0.383、扳歪 0.434），返回线把两个相位**同时**抬高，一减就没了 | 改成**同一相位**下"接上线/剪断线"两次直接比 |
| 尺子被稀释 | 整组 2400 个运动细胞取平均，看不出 1024 条边的作用 | 运动组在参考尺寸下是半饱和的（均值 0.507、46.7% 的细胞钉在 1.0），每格平均只摊到 0.43 条返回边 | 换成同相位直接比（见上），并承认读数很小 |

修好之后的实测（`artifacts/校准_新题_两臂.jsonl`）：

| 手臂 | 读数 | 判定（判据 0.00005） |
| --- | --- | --- |
| 剪断（增益 0），三种脚手架 | 0.00000 / 0.00000 / 0.00000 | 不过 3/3 |
| 接上（增益 1），三种脚手架 | +0.00018 / +0.00019 / +0.00017 | **过 3/3** |
| 接上（增益 4），一种脚手架 | +0.00072 | 过 |

读数随增益近似线性（每单位增益约 +1.7e-4），所以这道题不只是"有没有"，也能量"多强"。

### 2.3 返回线改成天生就有（因为它在搜索里原本等于不存在）

`live_config.json` 里 `association_return_gain` 从 **0.0 改成 1.0**。

| 项 | 内容 |
| --- | --- |
| 为什么原来不能是 0 | `screen_candidates.mutate` 的步长是"基因自己大小的四分之一"，出生值为 0 的基因用 `SCALE_FLOOR = 0.05`，一步最多走 4×0.05 = 0.2。增益 0.2 只让肌肉读数动 3.4e-5，**永远过不了 5e-5 的判据** |
| 结论 | 出生值 0 的基因 = 搜索永远碰不到的基因。要么把判据压到几乎为零（那就变成噪声），要么让这条线天生就有 |
| 选了什么 | 天生就有，和另外两个增益（扇入 1.0、回环 1.0）一致；"天生有线"本来也是这篇文章的题目 |
| 代价 | 出厂动物变了 → 全库 130 题重测；旧台账（121 只、128 题）成为"改前"记录 |
| 影响 | 返回线给每个运动细胞加约 0.0086 的输入，电机组读数动 1.6e-4 量级。逐题对照见第 4 节 |

### 2.4 第三道前额叶题

| 项 | 内容 |
| --- | --- |
| 题名 | `the_widest_layer_reaches_the_muscles`（组：前额叶） |
| 问 | 前额叶那一层动起来时，肌肉那头会不会跟着动 |
| 量 | 同一段被扳歪的姿势，接上返回线和剪断返回线各跑一次，**同一相位**下肌肉那几组的读数之差 |
| 判据 | ≥ 0.00005 |
| 出生动物 | 过（+1.6e-4 ~ +1.9e-4） |
| 成本 | 4 ~ 7 秒 |

它不是筛子（出生动物过），它是**断线报警器**：把返回线调弱或调没的候选会考不过。加上原来
那两道前额叶题，现在这一区有三条独立的读数：收到没有（`reads_the_body`）、留住没有
（`loop_holds`）、说出去没有（`reaches_the_muscles`）。

题库：126 → 128（关联区两题）→ **130**（今晚再加两题）。

## 3. 训练方式的问题与修法

| 问题 | 现象 | 改法 | 文件 |
| --- | --- | --- | --- |
| `probe` 档定义了却接不上 | `audit_taskbank.py --stage probe` 直接报错退出，一整场探测跑空 | 三处 argparse 的 choices 补上 `probe` | `tools/audit_taskbank.py`、`tools/screen_candidates.py`、`tools/confirm_kept.py` |
| 台账去重不分动物 | 一个文件里放两只动物时，后一只的题会被前一只的答案顶掉（我今晚真的踩到：`ret-on1` 的格把 `ret-on4` 顶了） | 去重键从 `(seed, task)` 改成 `(label, seed, task)` | `tools/audit_taskbank.py` |
| 没有并行 | 一场 1500 候选的筛选单进程要 3.9 小时 × 5 | 新增并行筛选器：N 个 worker，各自一个抽取种子、各自一个分片台账，跑完自动合并并出成绩分布 | `tools/round_parallel.py` |
| 全库成本没有写在明处 | 谁都不知道"每个候选都考全部题"要多少钱 | 写进 `PROBE` 的注释和这份文档第 1.1 节：**1000 候选 × 全库 = 447 小时** | `tools/taskbank.py` |
| 一个文件里混多个 label 时行数会骗人 | 合并台账的行数不等于候选数 | `round_parallel.py` 的收尾报告把"候选数 / 真建出来的动物数 / 各自过了几题"分开写 | `tools/round_parallel.py` |

| 题库对自己说的话是死文本 | 130 道题里 **126 道**的 `reads`/`bar_text` 是空字符串：`TASK_DOC` 那张表写得好好的，却没有任何一行代码把它接到 `TASKS` 上，于是 `--explain` 读的是空、`tests/test_taskbank.py` 里两条断言**在改之前就是红的** | 在 `TASK_DOC` 定义处把它接进 `TASKS`（题自己写过 `reads` 的就用自己的），接不上的直接报错退出 | `tools/taskbank.py` |

改完 `python -m unittest discover -s tests` **199 个测试全绿**（改之前是 2 个红的）。

并行筛选器怎么用（可续跑，分片存在就接着跑）：

```
python tools/round_parallel.py --candidates 1500 --workers 8 --stage probe \
    --scaffold 0 --genome-seed-base 40 --exam-seeds 0 --budget-minutes 150 \
    --out artifacts/轮5_筛选
python tools/screen_candidates.py --report --ledger artifacts/轮5_筛选.jsonl
```

要"第一道不过就停"就再加一个开关（见第 7.2 节，用之前先读那一节的代价）：

```
python tools/round_parallel.py --candidates 5000 --workers 8 --threads 1 \
    --stage probe --genome-seed-base 40 --exam-seeds 0 --stop-on-first-miss \
    --budget-minutes 120 --out artifacts/轮6_筛选
```

## 4. 返回线打开前后，逐题对照

出厂动物在返回线打开前后的两次全库审计逐题比对（`tools/compare_audits.py`，产物
`artifacts/_对照_返回线前后.json`）。要看的是：**除了这一条返回线，别的读数有没有动。**

| 项 | 数 |
| --- | --- |
| 题 | 改前 128，改后 130，两版都在的 128 |
| 新增 | 2（`the_widest_layer_reaches_the_muscles`、`keeps_its_line_towards_what_it_sees`） |
| 消失 | 0 |
| **结论翻转** | **5** |
| 读数动了（>0.0005） | 18 |
| 读数没动 | 7 |
| 读不出读数（没有 margin 配方） | 103 |
| 出厂动物总分 | 改前 **103/128** → 改后 **102/130** |

翻转的五题——**一题从不会变会，四题从会变不会**：

| 题 | 组 | 先修 | 改前 | 改后 |
| --- | --- | --- | --- | --- |
| `get_up_from_back` | 自救 | 无 | FAIL | **pass** |
| `nose_down_recover` | 自救 | get_up_from_back | pass | **FAIL** |
| `nose_up_recover` | 自救 | get_up_from_back | pass | **FAIL** |
| `stays_up_when_nudged_gently` | 站立 | stands_still | pass | **FAIL** |
| `walk_narrow_passage` | 地形 | walk_flat | pass | **FAIL** |

动得最大的正是翻身那几题的 up_z 读数：`get_up_from_back` 从 **-0.73 变成 +0.9998**
（真的从躺着变成站着），`nose_up_recover` 从 +0.62 掉到 **-0.81**，`get_up_from_side`
从 1.00 掉到 0.60，`stay_up_when_pushed` 从 0.785 涨到 0.947。
走路那几题动得小但方向一致（+0.004 ~ +0.005，`walk_flat`、`walks_without_being_told`、
`walks_for_twenty_seconds` 全朝一个方向），跟"返回线给每个运动细胞加约 0.0086 输入"对得上。

**所以这条线不是"只多了一根线"**：它把出厂动物的整片翻身行为重排了一遍——
**换来 1 个动作，丢掉 3 个动作**，站立和走路各被蹭到一点。
"出厂动物"换了人——这才有了这份对照，也有了把 130 道题在改后动物身上重跑一遍的必要。

## 7. 时间花在哪、省下来多少

### 7.1 一道走路题的钱，一步一步拆开

一只动物是 **58811 个细胞、222973 条边**（参考尺寸）。每步的钱，直接量：

```
python tools/measure_step_cost.py parts      # 下表
python tools/measure_step_cost.py build      # 每题开场固定开销
python tools/measure_step_cost.py walk-ab    # 下面那个 14.91 -> 9.34
```

| 每步 | 花在什么上 | ×1000 步 |
| --- | --- | --- |
| **3.7 ms** | 每步构造一份完整诊断字典（`controller.diagnostics()`） | **3.7 s** |
| 1.6 ~ 2.0 ms | 神经网络本身（`brain.step`） | 1.6 ~ 2.0 s |
| 1.4 ms | **改后**只问那一项（`scaffold_drift()`，含它自己那次权重表取回） | 1.4 s |
| 0.8 ~ 1.2 ms | 每步把整张 22 万条权重表取回主机再查上下界 + 查活动范围（harness checks） | 0.8 ~ 1.2 s |
| 0.42 ~ 0.44 ms | MuJoCo 物理（`body.step`，里面 5 个 2 ms 子步） | 0.42 s |
| 0.57 s（整题一次，热机） | 每道题重建机身 0.06 s + 重建脑 0.51 s | 0.57 s |

（同一个数在忙碌的机器上会高出一半：跑审计的同时量，`diagnostics()` 是 5.20 ms、
`brain.step` 是 2.56 ms。**量时间要在空机器上量**，这也正是 7.4 节那个坑的根源。）

一整道 10 秒的走路题（1000 步），同一进程同一只动物交替跑三轮：

| | 墙钟（`logs/测速_走路AB.log` 三轮） | 读到的 |
| --- | --- | --- |
| 改前（每步读整本字典） | **15.35 / 15.00 / 15.27 s** | progress 0.581，straightness 0.6236 |
| 改后（每步只问那一项） | **9.25 / 9.10 / 9.77 s** | progress 0.581，straightness 0.6236 |

**省 37 ~ 39%，读数逐位相同**（`progress_m`、`straightness`、`min_up_z` 三轮全一样）。

> 交代一件事：上表四行加起来约 4.9 秒，量出来省的是 5.57 秒，**对不上**。
> 差的那部分大概是旧写法每步多出来的临时数组——`np.abs(w - initial)` 那几个
> 22 万长度的中间结果每步约 9 MB，内存带宽被它占掉，连神经网络那一步也跟着慢。
> 所以这里的账我只把**逐项直接量到的**摆出来，不给一个"加起来正好"的假账。

那份诊断字典里有四项**每步都在算、每步都被扔掉**：`max_weight_change`（整张表做差、取绝对值、
取最大）、`memory_weights`（把记忆权重 **转成 Python 列表**）、`mean_activity`、`active_fraction`。
循环只留 `scaffold_max_relative_change` 一项。

| 改了什么 | 文件 |
| --- | --- |
| 新增 `scaffold_drift(weights=None)`：只算这一个数，用预分配缓冲**就地**算，不产生中间数组 | `born_wired/innate.py` |
| `run_seed` 的步循环不再构造整个字典，改成只问这一个数；权重表一次取回，查界和算漂移共用同一份 | `tools/validate_reflex_v3.py` |
| 采样（一次走路 20 个样本）原本一次读 **四遍** 诊断（`initial_sample` 里连调四次），现在读一遍 | 同上 |

`diagnostics()` 本身**没删**——`run_dog.py`、`evaluate_robot.py` 那些要整本字典的地方照旧用它；
拿掉的只是"每步读一次、读完扔掉"这一条路径。

整档一起看：出厂动物把八道筛选题全部问一遍，**改前 59.3 秒 → 改后 47.9 秒**，
八道题的判定**逐条和改前的审计一样**
（1.6+1.7+3.9+4.0+11.3+11.5+11.7+13.6 是改前那次的逐题墙钟）。
只快 19% 是因为这八道里只有四道是走路的（每步那份读数占得大），另外四道本来就便宜。

### 7.2 链：八道题问成一条链，第一道不过就停

`PROBE` 现在**按花钱从少到多排**，`stage_tasks("probe")` 也按这个顺序问
（原来按题库登记顺序，最贵的排最前）。`run_bank(..., stop_at_first_miss=True)`
配上 `round_parallel.py --stop-on-first-miss`：第一道不过就停。

同一批 24 个候选、同一台机器、同样 8 个 worker：

| 怎么跑 | 墙钟 | 每只动物 | 读到的东西 |
| --- | --- | --- | --- |
| 全档（八道都问） | 342.2 s | 112.0 s | 18 只至少过一题 |
| 链（1.6 秒那道起，不过就停） | **19.4 s** | **5.1 s** | 0 只过第 1 题，后七道没人到 |

**快 18 倍。**

> **代价，必须说清楚**：链只回答"它能走到第几级"，**不回答"它还会哪些题"**。
> 上面这 24 只里，全档有 18 只至少过一题（16 只过 `get_up_from_back`、2 只过
> `walks_in_a_straight_line`），链把它们**全部砍在第 1 题——18 只全丢**。
> 所以：**链是筛子，不是成绩单。** 用它从几万个候选里捞能过关的那几只；
> 不要用它给"每个候选会什么"打分。
> 台账里留着 `first_miss`（死在哪）和 `ran_tasks`（问过哪几道），
> 报告里"每题通过率"的分母是**"走到这题的有几只"**，不是"一共抽了几只"——
> 不然没人走到的题会显示成"没人做得出"。

顺带读出来一件事：**这一档的排序对它自己不利。** 第 1 题
（`the_association_loop_holds_what_it_was_given`）在 78+24+24 个候选里**一个都没过**，
链一上来就把所有候选砍光，"能走到第 4 题"这种信息永远出不来。
按"便宜的先问"排本身没错（它把 342 秒压成 19 秒），但要拿链**选**东西，
得先按数据把顺序再排一遍——第 4 题 `get_up_from_back` 的通过率是 **63.6%**，
它才是这一档里真正分得出人的那道。

### 7.3 这台机器上 GPU 和 CPU 引擎读数一模一样，GPU 更快

`BORN_WIRED_DEVICE` 决定走不走 torch/CUDA。同一只动物、同样五道题各跑一遍：

| 引擎 | 五道题墙钟 | 建脑 | 每步 |
| --- | --- | --- | --- |
| cuda（缺省） | 20.4 s | 0.641 s | 1.88 ms |
| cpu（numpy） | 21.5 s | 0.435 s | 4.66 ms |

**读数逐位相同**：两边都是 `passed = ['get_up_from_back']`，`直度 0.6236`、`2.6%`、
`gain 0.00564`，四条 `why` 字符串一字不差。8 worker 的一整场：GPU 19.1 s 对 CPU 39.1 s。
**所以筛选继续走 GPU**，CPU 只是"读数等价"的一个旁证。

### 7.4 一个坑：题库表里的墙钟不能当成本用

同一次审计里，`walk_flat` 记 **17.6 秒**，`walks_in_a_straight_line` 记 **11.7 秒**——
这两道题**注册的是同一个调用**（都是 `walk_measure(ctx, 10., "autonomous", "origin")`），
同一只动物、同一个进程，**差 50%**。`stands_still` 只模拟 6 秒却记 16.1 秒，
比模拟 10 秒的 `walk_flat` 还接近——固定开销压过了模拟时间。

所以"哪道题贵、贵在哪"要看 7.1 那种每步的直接量，**不要拿审计表里的墙钟当成本模型**。
第 1.1/1.2 节那张成本表里已经挂了"计时噪声"的注，这里给出它的一个极端例子。

> **另一件要交代的事**：第 4 节那份"改后审计"（`artifacts/审计_出生动物_返回线_s0.jsonl`）
> 的**墙钟被我自己的并发测量污染过**——跑它的时候我在同一台机器上开 profiler 和别的测量进程，
> 几个走路题的墙钟从 11 秒级涨到 40 秒级（`threads_the_passage_without_touching` 46.6 s、
> `backs_away_from_a_hand_on_its_chest` 42.6 s）。**通过/不通过的判定不受影响**（它是确定性的、
> 也和第 4 节的逐题对照一致），被污染的只有时间。要干净的时间请用 `无返回线_before_returnline`
> 那份，或者重跑一次。
