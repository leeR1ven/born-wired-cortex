# GPU 执行引擎（2026-09-27）

## 一句话

神经部分——突触电流、可塑性写入、整片细胞的电压与适应——现在在显卡上算。
公式一个字没改，连接规则、学习节拍、哪根线连到哪都没动。改的只是这些算式在哪里执行。

## 为什么要换执行器

大脑一步的开销几乎全在连接上：每步要给每条连接乘一次权重再加到目标细胞，
学一次要给每条连接算一遍局部规则再按每个细胞的预算缩放。这些量都正比于连接数，
而 CPU 上每个元素只做一两次算术，memory 带宽也用不满。这一步是典型的"多、但每个很便宜"，
正是显卡擅长的形状。内存也从来不是瓶颈：40.8 万细胞、118 万连接只占 0.86 GB。

## 中途发现的真问题：并行散射不可复现

最直接的做法是把 `np.bincount` 换成 `torch.index_add_`。它算得快，但**同一个模型、同一批输入，
跑两遍结果不一样**：

```
host   rerun  voltage identical: True   weights identical: True
device rerun  voltage identical: False  max diff 1.42e-14
```

原因是 CUDA 的散射用原子加，谁先到谁先加，加法顺序取决于线程块谁先跑完。
实测过的替代品里，`index_add_`、`bincount(weights=...)`、`cumsum` 都不确定，
只有**沿一个固定轴的归约**（`sum(dim=1)`）和 gather 是逐位确定的。

这对本项目不是小事：论文、指纹、实验结论都建立在"同样的东西跑出同样的数"上。
所以没有采用原子散射。

## 做法：把散射改写成固定次序的归约

`born_wired/torch_execution.py` 里的 `Segmented`：

1. 按目标细胞把连接排序，同一个细胞进来的连接就成了一段连续区间；
2. 把每段按"第几条"切成若干档，档宽按 4、12、36、108… 增长；
3. 每一档铺成一张（细胞数 × 档宽）的表，表里存的是连接编号，多出来的格用掩码置零；
4. 一行的和就是 `sum(dim=1)`——沿固定轴归约，次序固定。

档宽按三倍增长，所以填充量有上界（不超过连接数的约四倍），档数也少。
出货规模的真表：

```
兴奋连接 675,960 条 -> 1,687,832 格 / 8 档
抑制连接 434,128 条 ->   892,868 格 / 2 档
缩放用的两组各同上一份
合计 5,161,400 格，对应 1,110,088 条连接
```

代价是多做了几倍的访存，换来的是重跑逐位一致。归约次序仍和 NumPy 不同，
所以两个引擎之间还有浮点尾差——见下面实测。

## 实测：大脑一步（不含 MuJoCo）

`tools/probe_engine_speed.py`，先空跑几步热身，只计 `brain.step`：

| 每只眼 | 运动/本体/联想 | 细胞 | 连接 | host | device | 倍数 | 显存峰值 |
|---|---|---|---|---|---|---|---|
| 48×36（参考） | 200/64/256 | 49,042 | 190,532 | 8.3 ms | 6.8 ms | 1.2× | 72 MiB |
| 120×90 | 800/256/1024 | 246,370 | 802,194 | 27.4 ms | 12.1 ms | 2.3× | 310 MiB |
| **160×120（实时窗口）** | **800/256/1024** | **410,770** | **1,110,088** | **40.6 ms** | **14.1 ms** | **2.9×** | **406 MiB** |
| 240×180 | 1600/512/2048 | 882,866 | 2,260,402 | 88.9 ms | 25.9 ms | 3.4× | 844 MiB |

日志 `artifacts/engine_speed_scales.log`。模型越大差距越大——因为设备上真正贵的东西
已经不是连接，而是每步要在 host 和显卡之间搬的那几个整片数组（活动、外部电流）。
也就是说**再放大时，神经计算几乎不再涨**，剩下的是搬运和感知编码。

## 两个引擎差多少，各自稳不稳

`tools/compare_engines.py` 用同一份代码、同一个种子建两个控制器，跑同样 200 步：

```

  host     49042 细胞   190532 连接  18.63 ms/步   重跑逐位相同 True
  device   49042 细胞   190532 连接  11.19 ms/步   重跑逐位相同 True
  activity  最大差 2.773e-13   相对 2.773e-13
  voltage   最大差 2.773e-13   相对 1.755e-14
  weights   最大差 8.882e-16   相对 2.790e-17
  身体位置 host [-0.004156 -0.008087  0.314229]   device [-0.004156 -0.008087  0.314229]
```

三件事：两个引擎各自重跑逐位一致；两个引擎之间只差在第 13~16 位有效数字；
200 步之后身体位置六位小数完全相同。日志 `artifacts/compare_engines.log`。

行为对照也做了：`tools/probe_resolution_behaviour.py 400` 在 host 和 device 上各跑一遍，
五个分辨率的前进距离、最低高度、最小直立轴打印出来一模一样
（`artifacts/behaviour_after_gpu.log` 与 `artifacts/behaviour_after_gpu_host.log`）。

## 指纹

`tools/check_model_fingerprint.py` 现在按引擎分别记录（两个引擎的末尾几位本来就不同）：

```powershell

python tools/check_model_fingerprint.py --engine auto
```

写出的文件是 `artifacts/model_fingerprint_host.json` 与 `artifacts/model_fingerprint_cuda.json`，
各自再跑一遍都应打印"一致"。旧的无引擎字段的 `model_fingerprint.json` 不要再拿来比。

## 开关

环境变量 `BORN_WIRED_DEVICE`：`auto`（默认，有可用显卡就用）／`cpu`（保持 NumPy 引擎）／
其他值交给 torch。没有 torch 或没有显卡时自动退回 host，不会报错。
原来的 `RegulatedSynapses(..., device=...)` 也可逐个对象指定。

## 没搬到显卡上的部分

这一轮只搬了神经部分，下面这些仍在 CPU 上，而且是现在的实际瓶颈：

- **MuJoCo 物理与离屏渲染**（160×120 时约 23.5 ms/步）。
- **感觉编码**：视网膜采样、本体调谐、听觉回路（约 3.7 ms/步，160 个采样点逐点循环）。
- **控制器那一层 NumPy**：每步构造整片外部电流数组、按组写入口、每个接口的入参校验。

CPU 侧这些每步仍然要过整片细胞数组，所以设备版的一步耗时还是随细胞数线性增长。
想继续把模型做大，下一刀应该砍在这里，而不是连接。

## 限制

- 设备引擎是**可复现**的，但不是和 host 逐位相同。需要逐位复现旧结果的场合用 `BORN_WIRED_DEVICE=cpu`。
- 归约顺序变了，理论上极端病态的输入（大量正负抵消）会让两边差得更多；目前所有实测都在 1e-13 量级。
- 只支持 `RegulatedSynapses`（各控制器用的就是它）。`BoundedSynapses` 仍走 NumPy，
  旧单元测试因此逐位不变。
- 8 GB 显存下，240×180/1600/512/2048 用 844 MiB，还有余量；再大要先看显存。
