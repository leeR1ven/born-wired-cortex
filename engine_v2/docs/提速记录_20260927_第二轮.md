# 第二轮提速：出厂配置放大到 192×144，整步 17.1 ms 到 12.0 ms

现场：`models/reflex_arena.xml`，出厂 `live_config.json`＝视网膜 192×144、
运动 1600 / 本体 512 / 联想 2048，**584136 细胞 / 1812331 连接**，引擎 cuda。
所有数字来自同一台机器、同一份配置，改完再量一遍。

## 一、结论

| 阶段（`tools/profile_live_step.py`，120 步取均值） | 本轮开始 ms | 现在 ms |
|---|---|---|
| 身体感觉 `body_senses` | 0.19 | 0.20 |
| 眼睛 `eye_render` | 5.91 | **3.10** |
| 耳朵 `ear_relay` | 0.16 | 0.17 |
| 大脑 `brain.step` | 10.05 | **7.67** |
| 物理 `physics` | 0.83 | 0.84 |
| **整步** | **17.14** | **11.98** |
| 步/秒 | 58.3 | **83.5** |

改前那一刻的 160×120 / 800·256·1024（41.1 万细胞）是 12.33 ms / 81 步/秒。
也就是说现在出厂这套 **细胞多 43%、连接多 63%，整步反而比原来那套快 3%**。

顺带：改前 `eye_render` 的最大值是 71.7 ms（偶发卡顿），现在是 4.8 ms。
卡顿来自每个眼睛每步在主机上分配 3 MB 的 float32 临时数组（见下），
换成显卡上的原地运算后没有了。

同一套代码下的另外两档（`artifacts/_cfg_160.json`、`artifacts/_cfg_256.json`）：

| 配置 | 细胞/连接 | 整步 ms | 步/秒 |
|---|---|---|---|
| 160×120，800/256/1024 | 41.1 万 / 1.11 M | 9.39 | 106.5 |
| **192×144，1600/512/2048（出厂）** | **58.4 万 / 1.73 M** | **11.98** | **83.5** |
| 256×192，1600/512/2048 | 约 71.6 万 / 约 2.4 M | 18.58 | 53.8 |

出厂仍取 192×144：它比原来的出厂大、比原来的出厂快，两档都赢；256×192
是能跑但每一步 18.6 ms，放大代价换成时延，留作以后要更高分辨率时的选择。

## 二、三笔改动

### 1. 视网膜补丁均值搬到显卡（省 1.9 ms/步，最大一笔）

`RawEyes._report` 本来在主机上做：`uint8 → float32` 转换（0.58 ms）、
两次稀疏矩阵乘（0.11 + 0.19 ms）、除面积再四舍五入成 `uint8`（0.40 ms），
**每只眼 1.45 ms，两只眼 2.9 ms**。

现在同样的两次乘积和同样的取整在显卡上做，**每只眼 0.71 ms**。

为什么可以换地方算而结果一字不差：每个被加数都是不超过 255 的整数，
它的每一个部分和也都是整数，而整数在 float32 里精确（见 `_sampling` 的守卫）。
整数加法**与加的顺序无关**，所以主机只碰自己那几段和非零的算法，
和显卡上整行整行的稠密乘法，得到的是同一个整数。
`tf32` 会把这个性质毁掉（只有 10 位尾数），所以建表时若它是开着的就关掉。

**证明**：`artifacts/_verify_report_device.py` —— 随机扰动身体姿态产生
120 张各不相同的实际渲染图，显卡结果与主机结果**逐字节相同，0 处不符**。

### 2. 听觉回路编译（省 1.6 ms/步）

`AuditoryNeurons` 一次吃 160 个 16 kHz 采样（10 ms 的波形），
原来对每个采样跑 16 次 numpy 调用：一步 160×16 ≈ 2560 次调用，
**1.70 ms 全是解释器开销，不是算术**。

现在同一段递推用 numba 编译（`_advance_samples`），**0.125 ms**，
快 13.6 倍。逐条语句与原 numpy 行一一对应，包括哪个操作数在前，
因为 float64 的加法与顺序有关；`fastmath` 保持关着，否则编译器可以重排。

numba 是加速器不是依赖：没有它的时候走 `_advance_on_host`，那是同一段
原样的 numpy 循环，也是编译版要对齐的定义。

**证明**：`artifacts/_verify_auditory_numba.py` —— 两个同初值的回路，
一个走编译版一个走 numpy 版，400 步混合音频（噪声 / 弱信号 / 静音交替），
四个对外输出（`rates` / `orientation` / `spatial_rates` / `pinna_rates`）
以及内部的 `voltage`、`history`、游标**全部逐位相同**。
全量测试里的 `AUDITORY_BENCHMARK`：**4.24 ms → 0.349 ms**（每 512 采样）。

### 3. 同一张激励向量不再被扫四遍（省 0.8 ms/步）

激励向量从最外层进网络时，`RetinalInputNetwork` → `ReflexInputNetwork` →
`FeatureInputNetwork` → `AdaptiveNetwork` 四层各跑一遍 `_checked_in_place`，
每遍对 58.4 万个 float64 做一次全表有限性与下界检查，**一遍 0.64 ms**，
四遍就是在同一个数组上花 2.5 ms。

现在最外层检查一次，往下用 `check=False` 传下去。上一轮保留四遍的理由是
“每一层的 `+=` 都可能引入非有限值”，这一点并没有被放弃：**三处 `+=` 各自
都还在 `np.errstate(over="raise", invalid="raise")` 里**（`pixel_current`、
`reflex_input`、`features`），溢出与非法运算在那里当场抛出；显卡路径则由
录制步自带的三个谓词（突触电流有限、候选状态有限、适应量在区间内）接住。
`_checked_in_place` 现在多出来的是一个**默认开启的参数**，直接调用
`step_owned` 的读者拿到的校验与以前完全一样。

## 三、试过但没采用的

- 视网膜补丁均值改用**累积和**代替两次乘法：可以先做，但稠密乘法已经
  按上面那条整数性质对了，换写法只是换一个同样正确的式子，收益不明。
- 把 `_checked_in_place` 的两遍检查（`isfinite` 0.27 ms + `<0` 0.20 ms）
  合成一遍：要再引一个编译内核，收益约 0.3 ms，暂不值得。

## 四、证明没改坏

- **全量测试 155 项全过**（131.8 s，改动前 142.7 s），
  日志 `artifacts/tests_after_speedup3.log`。
- **跨引擎**（`tools/compare_engines.py`，200 步、49042 细胞）：
  两次重跑仍逐位相同；`activity` 最大差 **2.773e-13**、`voltage` **2.773e-13**、
  `weights` **8.882e-16**、身体位置六位小数 —— 与改动前的记录**一字不差**。
  （host 11.16 ms/步、device 5.22 ms/步，改动前是 12.22 / 6.69。）
- **行为**（`tools/validate_reflex_v3.py --duration 30 --seeds 0,1,2`，
  192×144 出厂配置，`artifacts/headless_192_final.json`）：
  三个种子全部 `status ok`、`behavior_pass true`、`no_resets true`、`error null`；
  最低 `up_z` 0.9895–0.9947（没倒），30 s 前进 0.55–0.66 m。
- **实时窗口**（`tools/live_dog.py`，跑 30 s 后读 `artifacts/live_v3_status.json`）：
  `engine cuda`、`neurons 584136`、`edges 1812331`、`brain_ms 7.72`、
  `sim_speed 0.624`、`error null`。

## 五、还剩什么

- `brain.step` 7.67 ms 里，主机侧仍有约 4 ms 是层层调用经过 Python 本身的
  开销（校验、字典、属性），与细胞数有关但与每一步的新计算无关。
- `update`（学习写回）每 5 步一次、约 4.8 ms，随连接数线性涨；
  它是连接数继续放大时第一个会挡住人的东西。
- `physics` 的 MuJoCo 渲染与 GL 上下文和 torch 在同一张卡上轮流用，
  眼睛那一段仍有约 1 ms 花在两边交接上，没有继续深挖。
