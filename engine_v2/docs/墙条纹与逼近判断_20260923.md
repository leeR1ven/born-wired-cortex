# 墙加条纹、以及「东西在变大 = 在靠近」（2026-09-23）

这一篇记录两件事：为什么给墙加条纹、加完以后墙的距离第一次能被视觉细胞读出来；
以及按「前一帧的特征细胞 + 后一帧的特征细胞 → 特殊细胞」接出来的**变大回路**，
实测在当前视网膜上一声不响。结论先写在前面。

## 一句话结论

- **墙加条纹：成了。** 墙的距离第一次能从视觉细胞读出来（0.3 m→1.8 m 单调），
  最近四档走 `brake` 减速，顶墙场景不再翻车。
- **「东西在变大 = 在靠近」那条逐列回路：在当前 32×24 的视网膜上量不出来**，
  9 组阈值 × 5 种运动全部为 0。根因是整幅画面一直在变（条纹墙占满视野），
  逐列的「这一列比刚才忙」没有信息；小球在 3 m 外只有 1~2 个像素。
- 真正在扛「看见近物就停/拐」的还是**变化量**那条路（会聚档 + 视差 + `near`/`brake`），
  它在墙上已经被量出来（下表）。

## 1. 为什么加条纹

纯色墙在渲染里几乎是黑的：贴到 0.3 m 时整幅画面只有 5~7 个灰阶，
`retinal_contrast` 对墙**没有任何输入**，所以「看见墙了」这件事从来没有发生过，
「别撞墙」一直全靠触觉。

`tools/build_arena.py`：

- 四面墙和 `front_block`/`left_block`/`right_block` 都改成 `material='striped'`。
- 新纹理 `models/wall_stripes.png`：2048×16，条宽从几何梯度
  `[3,4,6,9,14,21,32,48,72]` 里按固定种子 97 抽（非周期，免得远处几条看成一条），
  明暗两色 **243 / 88**（最初用的 238/16 渲染出来接近黑，等于白做），
  `texrepeat='1 1'`、`texuniform='false'`。
- 重跑 `python tools/build_arena.py`，`models/reflex_arena.xml` 与新纹理一起重新生成。

## 3. 条纹的代价，以及为什么眼睛只接 `brake`

条纹让**整幅画面**都在变：`retinal_change` 的均值从 0.25 升到 0.95，
`change_common` 的竞争抑制把整群按住，于是**会聚/距离档被顶死**：
原来纯色墙下 d=0.3 m 时七档全亮、`eye_convergence` 0.296，加条纹后同一个位置
`bank=[0.1,0,0,0,0,0,0]`、`eye_convergence` 0.000。

另一个坑：把最近四档同时接 `near[1]` 和 `brake`，在**顶墙**场景里会把狗走翻
（45 s 顶东墙：最低 up_z **−0.97**、接触 1182 拍）。根因是 `near[1]` 同时驱动
`avoid[0]` 和 `avoid[1]` 两条对立的转向通道，瞬时碰墙只持续一拍没事，
而眼睛的持续读数把两条对立的转向按住好几秒，步态就倒了
（`artifacts/wall_eye_gain_sweep.log`、`wall_eye_wall_gain.log`）。

修法（已做）：

- 眼睛的会聚档**只接 `brake`**（只减速，不抢转向），走自己的增益 `eye_wall_gain`；
  试过接 `wall_contact` 那一套（带转向），`eye_wall_gain` 给 1/2/4 全都翻（最低 up_z −0.99）。
- `eye_near_gain` 从 **1.0 降到 0.2**。

顶墙 45 s 回归（`artifacts/wall_eye_brake_gain.log`）：

| 变体 | x m | 最低 up_z | contact | 硬撞 |
| --- | --- | --- | --- | --- |
| 旧（near 1.0） | 1.888 | **−0.9706** | 1182 | 1090 |
| near .2 / brake 0 | 3.066 | 0.9476 | 29 | — |
| near .2 / brake 1 | 3.144 | **0.9829** | **45** | — |
| near .2 / brake 2（当前 live） | 3.144 | 0.9792 | 44 | — |
| near .2 / brake 4 | 3.116 | 0.9804 | 43 | — |

走路没被弄坏：竞技场 15 s，`near .2 brake 2` 与 live 完全一致
（x 0.610 / 最低 up_z 0.9958 / 接触 0 / yaw −32.5°）。

## 4. 「东西在变大 = 在靠近」这条回路：接线做了，量不出来

设计（`born_wired/embodied.py`，`eye_muscles` 里）完全照「前一帧 + 后一帧」这句话接：
每一列一个快细胞 `retinal_column`、一个慢痕迹 `retinal_column_trace`，
两个的差给出 `retinal_rise`（这一列比刚才忙）和 `retinal_fall`（比刚才静）；
「这一列刚变亮 ∧ 旁边一列刚变暗」合成 `retinal_outward` / `retinal_inward`；
两边一半看内、一半看外，同时亮 = 整幅画面在向外扩 → `eye_swelling`/`eye_growing` → `eye_looming` → `brake`。
诊断入口 `diagnostics()['eye_loom']`，量测工具 `tools/measure_loom.py`。

实测**全是 0**，换阈值也救不回来：

| 场景 | `eye_change_threshold` × `eye_flow_threshold` | outward / inward / growing / looming |
| --- | --- | --- |
| 静止站墙前 3.0 m | 0.02×0.1 → 0.10×0.4（4 组） | ≤0.010 / ≤0.010 / 0 / 0 |
| 眼睛被手动扫 3 rad/s | 同上 | ≤0.010 / ≤0.010 / 0 / 0 |
| 小球 3 m→0.35 m（0.5/1.5/3.0 m/s） | 同上 | 0（见下） |
| 自己走向墙 0.6 / 1.6 m/s | 同上 | ≤0.083 / ≤0.081 / 0（见 `artifacts/loom_wall.log`） |
| 侧向平移 0.6 m/s、后退 0.6 m/s | 同上 | 同上 |

日志：`artifacts/loom.log`、`artifacts/loom_ball.log`、`artifacts/loom_wall.log`。

两条根因，都不是调参能修的：

1. **整幅画面一直在变。** 条纹墙占满视野时 `retinal_change` 的均值
   静止不动也有 **0.85~0.94**（`loom_ball.log` 第一列）。这一列"比刚才忙"
   的差别被淹没：`fall` 在静止场景就已经 0.86，`outward` 恒 0。
   和上一段 `change_common` 顶死会聚档是同一个坑。
2. **小球太小。** 半径 0.06 m 的球在 3 m 外只有 1~2 个像素、1 m 外只有 3~5 个像素，
   连已经验证过的视差/会聚那条路都读不到它：`loom_ball.log` 里
   球从 3.0 m 走到 0.35 m，`bank` 全程 0.100（= 一档都没亮）。
   这不是回路的问题，是视网膜不够大——用户也拍板过"要分得更精细需要更大的模型"。

## 5. 备选方案量过了：会聚档上确实有"在变近"的信号，但不值得再走一遍

把同一句原理（前一刻的细胞 + 这一刻的细胞）接到**已经能用的会聚档**上，
看「有一档刚刚亮起来」能不能当成"在靠近"。跑自己走向墙
（`artifacts/band_ramp.log`，档位和 = level，ramp = level − 它自己 1 s 的慢均值）：

| 场景 | 亮着的档 首/中/尾 | level | ramp 均值 |
| --- | --- | --- | --- |
| 静止 | 1/1/1 | 0.148 → 0.100 | −0.008（最大 0） |
| 侧向 0.6 m/s | 1/1/2 | 0.161 → 0.170 | +0.013（最大 0.094） |
| 走向墙 0.6 m/s | 2/1/1 | 0.197 → 0.163 | −0.004 |
| 走向墙 1.6 m/s | 1/2/**6** | 0.160 → **1.954** | **+0.544** |
| 后退 0.6 m/s | 2/1/1 | 0.196 → 0.100 | −0.023 |

快的逼近（1.6 m/s）下档位一路点亮，静止恒定、后退为负——**信号是有的**。
但它和墙距走的是同一个出口（会聚档 → `near`/`brake`），再接一遍不增加新功能，
所以没有接。慢速（0.6 m/s）下反而不亮，这也是诚实的限制。

## 6. 测试

- 全套 **139 项、0 失败**（`artifacts/tests_after_stripes_fixture.log`）。
- 加条纹后曾有 2 项失败（`test_eye_muscles.py`：远处球点亮的档位少一档、
  近处两眼的会聚角为 0）。根因**不在脑，在夹具**：那两个用例本来就靠
  "把布景搬开、只量眼睛回路"（文件开头就是这么写的），但**墙也算布景**，
  以前墙是纯色等于不存在，现在墙有条纹，眼睛就去盯着墙（房间里最近的面）而不是球。
  修法是把四面墙加进夹具的 `SCENERY` 一起搬开，没有动任何阈值。
- 新增工具：`tools/probe_wall_distance.py`（墙距）、`tools/measure_loom.py`（变大回路）。
