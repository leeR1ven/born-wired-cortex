# 代码接线审计（2026-09-14）

## 为什么要做这件事

以前出现过"功能写了、但根本没接上"的情况：程序跑起来一切正常、数字也好看，
可那段代码其实一次都没执行过，真出了问题也发现不了。

所以本次做两件事：

1. **静态扫描**：全仓库找出"定义了、却没有任何地方读取"的类、函数、方法。
2. **运行时接线自检**：给模型装上计数器，真跑一遍闭环主流程，
   报告"这次运行里哪些部件整场没被碰到"。
   工具：`接线自检_wiring_audit.py`（本次新增，见文末用法）。

## 五、最要紧的三条

### 1. "把大量外界信号压缩成少量信号"这一步，闭环里根本没走

`闭环流程_closed_loop.py` 是这样喂输入的：

```python
视出 = 视觉.网.前向传播(np.random.uniform(0, 1, 视觉.池.总数)).astype(bool)
听出 = 听觉.网.前向传播(np.random.uniform(0, 1, 听觉.池.总数)).astype(bool)
```

它把**随机噪声**直接灌进前处理网络的输入层，完全绕过了
`降采样 → 蛇形像素 → 图像转信号`（视觉）和 `压缩频谱 → 频谱转信号`（听觉）。

而"多层网络是为了把大量外界信号压缩成少量信号"正是这个架构的核心主张之一。
也就是说：**目前这条闭环测试并没有验证压缩这一步**，它验证的是压缩之后的部分。
`解码亮度` / `解码响度` 也从没跑过，所以"压完之后还能不能还原"同样没被验证。

### 2. 运动反向网络的召回路径从没跑过，天生镜像底版等于没生效

`反向赫布网络` 在闭环里只被调用了 `学习一帧`，
`前向`（召回）一次都没执行，所以它内部的 `镜像投票`（文档里的
"③ 天生镜像底版：让没学过的全新命令码也先给出肌肉的大致位置"）**从未生效**。
`解码发力` 也没跑过，所以"命令码到底还原成了多大的肌肉发力"没有在闭环里被检查。

### 3. 海马索引新写的加速路径没有调用方，而且打印标签会误导人

未提交的改动在 `海马索引` 里新加了 `锁定全键` + 一套位图缓存（`_取全键缓存` /
`_登记全键缓存` / `清除全键缓存`）。实测：**没有任何调用方，一次都没执行**。

而闭环里实际调用的是 `锁定胜出`（`闭环流程_closed_loop.py:162`、`:216`），
但打印出来的行却写着"海马索引锁定时间"，容易让人以为走的是 `锁定时间`。
`锁定时间` 本身在闭环里也没被执行（只在 `前额叶区_prefrontal.py` 自己的
`__main__` 自检里用过）。

## 六、接线自检工具用法

```powershell
cd 本机工作目录
& 'C:\Users\Administrator\AppData\Local\Programs\Python\Python313\python.exe' -X utf8 接线自检_wiring_audit.py 8
```

参数是帧数（默认 8 帧，几秒出结果）。报告四节：

- 【一】每个部件被调用多少次（**导入阶段 / 运行阶段分开列**）
- 【二】加载时就存在的单例（不会重新实例化，但方法调用会被计数）
- 【三】整个部件本次完全没被碰到
- 【四】部件被用到了，但里面某些方法一次都没执行

说明（第一版曾在这里出错，已修正）：
工具用 `builtins.__build_class__` 钩子，在**类被创建的那一刻**就装上计数器，
所以"模块加载时执行的代码"（例如 `视觉前处理.神经网络` 出生时的 `_校准输出α`
输出亮数校准）也会被计入，归到"导入阶段"。
第一版是在模块导入之后才装计数器，把这类导入期执行的方法误报成"从没执行"，
现已修正并复跑验证。

> 注意：它是**运行时**证据，只覆盖"这次跑的这条流程"。
> 换入口（比如跑闭环仿真或 full_model）要重新跑一次，且需要换模块清单。
