# 架构收敛方案（2026-09-14）

## 一、结论：不重写，做收敛

**理由**

1. 问题不在架构错，在于**同一个架构散成了 6 份**。重写不能解决散，只会变成第 7 份。
2. 论文里所有已验证的实验证据都出自这些代码。重写等于把这些证据全部作废。
3. 你说"整体架构脑子里很清楚"——那就说明架构本身没丢，丢的是**散落的实现细节和小规则**。
   这正是"抽出来给你核对"能解决的，不需要重写。

**但要做的是一件"重写级"的事**：把架构的规则和参数收敛到**一处**（单一真源），
其余代码向它对齐。这比全量重写便宜得多，也正好解决"忘了小规则"。

### 3.2 一条已经踩过坑的：权重增长规则被写了三遍，骨架那一版是旧的最弱的

**文字网络实验的结论**（2026-09-14，已发表级证据）：
让"权重越高的连接越难再长"这条规则的强度加大后，
同样 3.448 亿字，思考的广度从 913 涨到 **2051**（翻倍多），后半程还能冒出的新字多了 3.6 倍。
胜出形式：`Δw ∝ a / (1+w)³`（记为 power3）。

现在这条规则在仓库里**有四个不同的实现**：

| 实现 | 位置 | 形式 |
|---|---|---|
| 文字网络（旧，已发表） | `语言规模实验…/hebb_text.py` | `Δw ∝ a/(1+w)` |
| 文字网络（新，已验证更好） | `语言规模实验…/fast_hebb_power.py` | `Δw ∝ a/(1+w)³` ← **胜出** |
| full_model | `full_model/brain.py:42 SaturatingConnections` | `rate × remaining^potentiation_power` |
| legacy | `legacy/weight_dependent_plasticity.py:32 SoftBoundConnectionTable` | `ceiling` + 权重相关抑制 |
| **骨架（根目录）** | `权重连接管理_weight_manager.py` | **恒等 `强化量=1.0`，没有这条规则** ← 最弱的一版 |

→ 典型症状：在文字网络里辛苦验证出来的规则，**从来没接到骨架的 `连接表` 上**。
这就是"某些地方没用上却不知道"的实例，而且是有论文级证据支撑该怎么改的那种。

## 四、第一批要做的（建议顺序）

1. **定骨架**：根目录原架构确认为唯一"架构规格"；`v2` 移到归档目录并加说明文件。
2. **补接线断点**（已定位，见 `代码接线审计_20260914.md`）：
   - 闭环改成喂**真信号**（走 `降采样 → 蛇形像素 → 图像转信号` / `压缩频谱 → 频谱转信号`），
     再加 `解码亮度` / `解码响度` 对拍 → 才真正验证"压缩"；
   - 闭环补上 `反向赫布网络.前向`（召回）+ `解码发力` 检查 → 让天生镜像底版真的生效；
   - `锁定全键`：要么接上（并加自检），要么撤掉；顺手把打印标签里误导人的
     "海马索引锁定时间"改成实际调用的 `锁定胜出`。
3. **删死代码**：`反向赫布网络旧版`、`速率微步`/`速率投影`、`SimpleWorld`、`纯权重控制.重置`。
4. **把 power3 规则接进骨架的 `连接表`**，并在闭环里做前后对照（文字网络已有现成的测量方法）。
5. **逐条回流机制**（3.1 表）：每个机制走同一套流程——
   写进骨架 → 在闭环里接上 → 跑接线自检确认它真的被执行 → 记一条规则进总表。
