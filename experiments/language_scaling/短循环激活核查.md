# 短循环的实际激活过程

核查对象：`short_context_v2/decay_0p25/model.npz`，简化字符赫布模型。只读追踪，没有修改学习核心、权重、参数或旧实验文件。

当前实现中，多个近期已输入或已输出字符共同影响下一字。所有输出候选的电流则属于一次选字的临时计算，不会把这些候选全部写回持久活动。它们竞争同一个下一字位置，不是已经排好顺序的多个未来字。加两轮传播时，中间传播活动也不会跨输出保存。

原始程序的 `generate()` 每次选择电流最高的一个字符，再把这个字符作为新输入交给 `observe()`。选中模型的活动衰减为 0.25，阈值为 0.02；若最近字符各不相同，只有最近三个字符保持活动，按从旧到新分别为 0.0625、0.25、1。没有重复使用后的疲劳或动态阈值状态；这一点只描述这个简化模型。

从保存的第一条实际续写逐步追踪，观察到下面的循环：

| 参与预测的字符（旧 → 新） | 输出 | 更新后的字符 |
|---|---|---|
| 道、你、們 | 的 | 你、們、的 |
| 你、們、的 | 人 | 們、的、人 |
| 們、的、人 | 道 | 的、人、道 |
| 的、人、道 | 你 | 人、道、你 |
| 人、道、你 | 們 | 道、你、們 |

五次输出后，活动字符、活动数值及浮点累加使用的字典顺序都回到原样。持续增长的时间计数没有进入预测计算，权重也保持不变，因此之后继续产生同样的输出。这是整个决定输出的活动状态形成循环，不需要存在某个字直接激活自身的连接。

多个字确实共同作用。例如从“你、們、的”输出“人”时，三条边贡献为：

- 你 → 人：活动 0.0625 × 权重 2.46989346，电流约 0.15437。
- 們 → 人：活动 0.25 × 权重 2.00371838，电流约 0.50093。
- 的 → 人：活动 1 × 权重 17.42205048，电流约 17.42205。

较早两个字不是没有参与，而是贡献之和远小于最后一字的贡献。这一状态再次出现时，同样的合力再次选择“人”。

核查使用四条原始提示，分别以零轮和两轮额外传播各生成 64 字，共八条轨迹；前 48 字均与原实验保存的续写完全一致。八条轨迹均出现五步活动周期。核查保留活动字典顺序并逐步比较，所有后续周期均相同。

这说明当前实现没有覆盖“尚未输出的预激活候选持续保留、与新输入共同演化”的机制。它不能据此评判那种机制是否有效；同时，仅有多个单元共同活动，也不保证只能出现长循环。

追踪脚本：`inspect_short_cycle.py`。

原始证据及源文件哈希：`short_context_cycle_audit_v1/activation_trace.json`。其中包含每步的持久活动、前五候选、电流贡献、输出后活动和首次重复位置；没有采用禁止重复或替换输出的规则。
