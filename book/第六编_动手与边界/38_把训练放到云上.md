# 第 38 卷　把训练放到云上（并行、看门狗、流式加载、结果怎么拉回来看）

> **本卷目标**：把"在自己电脑上跑不动"这件事，变成**一套能过夜跑、早上看结果的流程**。

---

## 38.0 一句话原理

> **本地跑慢不是因为算法慢，是因为机器小。**
> 上云要做四件事：**把环境弄对、把进程开对、让它自己关机、把结果拉回来**。

---

### 生活里的比喻

**在自己电脑上跑，像在书房里做木工**：工具顺手，但房间就那么大，
你一开机器，整间屋子的灯都得为它让路，别的活全干不了。

**放到云上，像租了一间不熄灯的车间**：机器多、随便开，
但——**门锁要你自己配（密钥）、班次要你自己排（并行度）、下班要你自己关灯（看门狗）**。
**这三件事没安排好，账单会替你上课。**

## 38.1 环境：三个必须弄对的地方

| 项 | 正确做法 | 错了会怎样 |
|---|---|---|
| **图形后端** | **必须 `MUJOCO_GL=egl`** | 掉到 Mesa **软件光栅**，**慢 177 倍** |
| **核数** | **用你自己配置的核数** | 容器里 `nproc` 报的是**宿主机核数**（见过报 96，**实际只有 24**） |
| **依赖版本** | 钉死版本 | 结果对不上 |

### 钉版本（`engine_v2/requirements.txt`）

| 包 | 版本 |
|---|---|
| numpy | **2.4.6** |
| mujoco | **3.13.0** |
| scipy | **1.17.1** |
| numba | **0.65.1** |
| pillow | **12.2.0** |
| torch | **2.7.1** |

> **`nproc` 这一条特别坑**：它**不报错**，只是你开了 96 个进程、实际只有 24 个能跑，
> **四个进程抢一个核**，整体反而慢。

## 38.2 一个必须记住的命令行坑

| 命令 | 后果 |
|---|---|
| `pkill -f 'evolve_chase'` | **匹配到自己这条 ssh 命令行**，把会话**杀掉** |
| **`pkill -f 'evolv[e]_chase'`** | ✅ 正确 |

**为什么中括号能解决**：`[e]` 在正则里匹配 `e`，
但**字面上包含 `[e]`**，所以它**匹配不到自己**——自己的命令行里写的是 `evolv[e]_chase`，不是 `evolve_chase`。

> **这是一个"你以为在停别人的车，结果把自己刮了"的经典坑。**

## 38.3 跑完自己关机：看门狗

| 步 | 做什么 |
|---|---|
| 1 | 监视训练进程有没有结束 |
| 2 | 结束后**打包结果** |
| 3 | **等 20 分钟** |
| 4 | **关机** |

**为什么要等 20 分钟**：给"拉结果 / 补跑 / 抢修"留一个窗口。
一跑完立刻关机，你就**没法在机器还活着的时候查任何东西**。

**相关文件**：`engine_v2/tools/_watchdog.sh`、`_restart_watchdog.sh`、`engine_v2/_watchdog3.sh`

## 38.4 并行：一次跑一批

| 做法 | 说明 |
|---|---|
| 一批模型里**同时跑多个** | 把核用满，但**别超过你实际的核数** |
| 一批的规模 | 例子：**8 代 × 每代 1,000 只** |
| 脚本 | `engine_v2/_云三批.sh`、`engine_v2/tools/_云二批.sh`、`round_parallel.py` |

> **并行最容易踩的坑不是"开太多"，而是"开太多但以为自己没开太多"**——见 38.1 的 `nproc`。

## 38.5 流式加载

| 项 | 说明 |
|---|---|
| 是什么 | 训练/回放时**边收边用**，不必等整个文件落地 |
| 好处 | 长训练里"看进度"这件事不用等到最后 |

## 38.6 结果怎么拉回来看

| 步 | 做什么 | 脚本 |
|---|---|---|
| 1 | **拉回本地** | `engine_v2/tools/_pull_cloud.ps1` |
| 2 | **生成成绩单** | `engine_v2/tools/_batch_report.py` |
| 3 | 看每一代的几个数 | 建出来几只、没摔几只、会朝球走几只 |
| 4 | 看复试留下的 | 每一代最好的几只 |
| 5 | 看整体最好的 | 贴到球几个 / 看球位置几个 / 考试几趟 / 最近跌到多少米 |

> **看成绩单不要只看"最好的那只"**——要看**每一代的中位数和录取数**，
> 否则你会被一只偶然的好模型骗（第 37 卷）。

---

## 38.7 一条"别浪费机时"的纪律

| 纪律 | 说明 |
|---|---|
| **上云之前先在本地跑通 1 只** | 云上跑 8 小时才发现脚本有错，是最贵的错 |
| **上云前先冒烟** | 小规模跑一批，确认能出结果 |
| **别重跑已经跑过的题** | 用户明确说过：**云端可以更新了，不用再跑以前的测试了** |
| **跑完的机器要能自己关** | 见 38.3 |

---

## 38.8 脚本里的两个文件格式坑

| 文件类型 | 编码要求 |
|---|---|
| **含中文的 `.ps1`** | **UTF-8 带 BOM** |
| **`.sh`** | **不能带 BOM** |

**为什么相反**：PowerShell 读 `.ps1` 靠 BOM 认编码；而 Shell 会把 BOM 当**命令的一部分**，直接报错。

## 38.9 怎么搭

| 产出 | 要点 |
|---|---|
| **一个环境检查** | `MUJOCO_GL=egl`、核数、依赖版本 |
| **一个启动脚本** | 按**实际核数**开进程 |
| **一个看门狗** | 跑完打包 → 等 20 分钟 → 关机 |
| **一个冒烟脚本** | 小规模先跑一遍 |
| **一个拉回 + 出成绩单的脚本** | `_pull_cloud.ps1` + `_batch_report.py` |

## 38.10 怎么验证

| 你想确认的事 | 怎么验 |
|---|---|
| EGL 真的生效了吗 | 比一步耗时；没用 EGL 会慢**两个数量级** |
| 核数用对了吗 | 查**自己配的**核数，别用 `nproc` |
| 看门狗真的会关机吗 | 看日志里有没有"关机"这一步；或**ssh 连不上**就是关了 |
| 结果真的拉回来了吗 | 本地成绩单里的数字应该和远端的**对上** |
| 冒烟真的过了吗 | 小规模那批要有**完整的结果文件** |
| 有没有白跑 | 对照"这次要验证的那个机制"，多余的重跑要能说清**为什么** |

---

## 38.11 常见坑

| 坑 | 症状 | 正确理解 |
|---|---|---|
| **没设 `MUJOCO_GL=egl`** | 慢 177 倍 | 必须设 |
| **按 `nproc` 开进程** | 四抢一，整体更慢 | 用**实际核数** |
| **`pkill -f 'evolve_chase'`** | 把自己会话杀了 | 用 **`evolv[e]_chase`** |
| **跑完立刻关机** | 想查什么都不能查 | **等 20 分钟** |
| **`.ps1` 无 BOM** | 中文乱码 | **带 BOM** |
| **`.sh` 带 BOM** | Shell 报错 | **不带 BOM** |
| **没冒烟就上大任务** | 跑几小时才发现脚本错 | **先小规模跑通** |
| **重跑旧测试** | 白烧机时 | 用户明确说过**不用再跑以前的测试** |
| **只看最好那只** | 被偶然骗 | 看**中位数和录取数** |
