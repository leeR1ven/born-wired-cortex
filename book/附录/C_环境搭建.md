# 附录 C　环境搭建：本机 Windows / Linux / 云服务器

> **本附录目标**：让一个**没碰过这个项目的人**，能在三种环境下把东西跑起来。
> 顺序是**先本机、后云上**——因为**云上跑 8 小时才发现脚本有错，是最贵的错**。

## C.5 云服务器（这部分最值钱）

### 一套完整的过夜流程

| 步 | 做什么 | 要点 |
|---|---|---|
| 1 | **登录** | `ssh -p <端口> root@<主机>` |
| 2 | **检查环境** | `MUJOCO_GL=egl` 设了吗？核数是多少？依赖版本对不对？ |
| 3 | **冒烟** | **小规模先跑一批**，确认能出结果 |
| 4 | **启动训练** | 按**实际核数**开并行 |
| 5 | **装看门狗** | 跑完**打包 → 等 20 分钟 → 关机** |
| 6 | **睡觉** | —— |
| 7 | **第二天** | **拉回结果** → **出成绩单** → 看每一代的数 |

### 三条必须记住的环境坑

| 坑 | 症状 | 正确做法 |
|---|---|---|
| **没设 `MUJOCO_GL=egl`** | 掉到 Mesa 软件光栅，**慢 177 倍** | 登录后**先 export** |
| **按 `nproc` 开进程** | 容器报的是**宿主机核数**（见过报 96，实际只有 24）→ 四抢一，整体更慢 | 用**自己配的核数** |
| **`pkill -f 'evolve_chase'`** | **匹配到自己这条 ssh 命令行**，把会话杀掉 | 用 **`evolv[e]_chase`** |

### 拉回结果

| 步 | 命令 / 文件 |
|---|---|
| 拉回本地 | `powershell -NoProfile -ExecutionPolicy Bypass -File engine_v2\tools\_pull_cloud.ps1` |
| 出成绩单 | `python engine_v2\tools\_batch_report.py` |

**成绩单里要看什么**：**每一代**的建出来几只、没摔几只、会朝球走几只；
**每一代复试留下的最好几只**；**整体最好的 3~5 只**（贴到球几个、看球位置几/18、考试几/4 趟、最近跌到多少米）。

> **不要只看最好的那一只**——那是最容易被偶然骗的地方（第 37 卷）。

## C.6 文件格式的两个坑（很花时间，先记下来）

| 文件 | 要求 | 错了会怎样 |
|---|---|---|
| **含中文的 `.ps1`** | **UTF-8 带 BOM** | 中文乱码，脚本报错 |
| **`.sh`** | **不能带 BOM**（LF 换行） | Shell 把 BOM 当命令，直接报错 |

> **为什么两者相反**：PowerShell 靠 BOM 认编码；
> 而 Shell 读第一行是 `#!...`，前面多一个 BOM 就变成"**找不到这个命令**"。

## C.7 一个"版本太低"的情况怎么办

云上镜像有时**只有很老的 Python**（比如只剩 3.8）。
这时有两条路：

| 路 | 做法 | 取舍 |
|---|---|---|
| **换镜像** | 找带新版 Python 的基础镜像 | **首选**：省事 |
| **自建环境** | 在这台机器上装新 Python | 慢，但不受镜像限制 |

> **原则**：**先确认依赖能装上（numpy 2.x / mujoco 3.x）再开始训练**。
> 装不上的话，**后面所有结果都不可信**。

## C.9 常见坑

| 坑 | 症状 | 正确理解 |
|---|---|---|
| **不钉版本** | 结果和上次对不上 | 照 C.2 钉死 |
| **云上忘设 EGL** | 慢两个数量级 | 登录先 export |
| **按 `nproc` 开进程** | 越开越慢 | 用实际核数 |
| **`.ps1` 无 BOM** | 中文乱码 | 带 BOM |
| **`.sh` 带 BOM** | 报"找不到命令" | 不带 BOM |
| **没冒烟就上大任务** | 浪费几小时 | 先小规模 |
| **跑完立刻关机** | 想查什么都查不了 | 等 20 分钟 |
| **只看最好那只** | 被偶然骗 | 看中位数和录取数 |
| **在云上调代码** | 改一行要传一次 | **本地写、本地测、上云只跑** |
