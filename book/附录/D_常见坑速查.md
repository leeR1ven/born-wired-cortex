## D.3 环境 / 命令

| 现象 | 原因 | 怎么办 |
|---|---|---|
| **慢两个数量级** | 云上没设 `MUJOCO_GL=egl` | export 一下（第 38 卷） |
| **进程四抢一、整体更慢** | 按 `nproc` 开了进程 | 用**实际核数** |
| **ssh 会话被切断** | `pkill -f 'evolve_chase'` 匹配到自己 | 用 `evolv[e]_chase` |
| **`.ps1` 中文乱码** | 没带 BOM | 存成 UTF-8 **带 BOM** |
| **`.sh` 报"找不到命令"** | 带了 BOM / CRLF | **不带 BOM**，LF 换行 |
| **`python` 找不到** | 不在 PATH | 用**全路径** |
| **删文件被策略拦** | —— | 用补丁工具的删除语法 |
| **补丁把行首 `+` 写进文件** | 补丁没被当成补丁解析 | **确认补丁格式**（本文档自己踩过） |

## D.4 方法论（最贵的一类）

| 你正在做的事 | 为什么不对 | 该怎么做 |
|---|---|---|
| **手改几根连接让它"会"** | 手调出来的**没法复现、也长不大** | 随机生成 + 考试 + 筛选 |
| **参数没调好就加代码补** | 被用户点名批评的**同一个毛病** | 回去**调参数**（第 31 卷 31.3 是范例） |
| **加一条"整体压低权重"** | **红线**：稳定性是更新规则的性质 | 看论文 P10、第 20 卷铁律 3 |
| **加一个"专注开关"** | **代码替神经元做决定** | 专注是**结构的结果**（第 26 卷） |
| **为了调参数专门做实验** | 那是**大批量训练**的事 | 你只需判断**机制可行**（第 36 卷） |
| **每加一个机制就重跑全部实验** | **没必要**（用户明确说过） | **只做验证这个机制的实验** |
| **把"感觉太小"当结论** | 拍脑袋 | 量出来（第 29 卷 29.6） |
| **把草稿当成果** | 会污染结论 | 标"未采用"（第 34 卷 `未采用说明.md`） |
| **被推翻的说法悄悄改掉** | 别人对不上 | **写"撤回"**，登记在**附录 A** |

## D.5 一张总表：**所有坑的两条根**

> **绝大多数坑，本质上是同一件事的两面**：
>
> **① 让代码替神经元做了决定**
> **② 把"没做到"说成了"做到了"**
>
> 遇到任何奇怪的现象，先问这两句。
