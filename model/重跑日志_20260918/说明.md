# 这批日志是什么（2026-09-18 重跑，**不是**论文引用的那批）

2026-09-18 排查"出生就会的那一走为什么会摔倒"时，把 `model/` 下的脚本重跑了一遍，
它们的输出同名写在脚本旁边，于是和仓库 `logs/` 里**论文真正引用的那批**（2026-09-16）
重名。两份来自**不同的配置**：

| | `logs/`（论文引用） | 这里这批（2026-09-18 重跑） |
|---|---|---|
| 前额叶 | 53,200 个皮层神经元 | **57,436** 个皮层神经元 |
| 合计 | 143,796 个皮层神经元 | **148,032** 个皮层神经元 |
| 前额叶回响 | 关（论文 R1&ndash;R8 用这一档，见方法 5.5） | 开（动态整体抑制那时已改默认开） |
| 站起来末高 | 0.261 米 | 0.180 米 |

所以两份日志里的数字**本来就该不一样**，它们各自对、各自说明一件事：
`logs/` 那批支撑论文里 R1&ndash;R11 的每一个数字；这里这批支撑 2026-09-18 的摔倒修复记录
（见 `docs/修复_摔倒_20260918.md`）。README 的"诚实声明"一节用的是后者的数字。

把这一批挪进这个子目录，是为了让 `model/核对_论文数字.py` 不再误读它们
（那会让 6 条本来对得上的数字被误报成对不上）。核对脚本现在**以 `logs/` 为准**，
如果脚本旁边又出现同名日志且内容不同，它会在报告末尾单独标出来，不会静默采用。
